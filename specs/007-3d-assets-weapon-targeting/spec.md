# 功能規格：3D 資產與武器瞄準整合

**功能分支**：`007-3d-assets-weapon-targeting`

**建立日期**：2026-08-28

**狀態**：實作完成，待 PR 審查（T058 FPS 尚未量測）

**輸入**：使用者需求：「整合 `遊戲3d/` 中的敵人與大樓模型，統一 OBJ 方向；RPG 要有準心並使用手槍射程；多目標防空炮要使用更大的白框、支援無固定數量的多目標鎖定、全數鎖定後一次發射多枚導彈，且白框大小可升級；RPG 發射時要看見綠色長方體子彈，陸地自動防禦要有砲台與敵人相同的曳光發射效果，並限制射程、傷害與射速；3D 模型要轉成正確方向且不同模型不可互相混用或發生顏色污染；主選單要新增設定按鈕，讓玩家選擇新版或舊版防空武器瞄準介面，舊版恢復以圓圈鎖定飛機。」

**版本覆寫說明**：本功能的 FR-025～FR-028 是目前陸地自動防禦規則的唯一來源，
覆寫 006 版文件中每小關 20 發、1.5 秒冷卻、20 點傷害與僅攻擊非魔王小兵的舊契約；
006 文件保留作為前一版本的歷史記錄，不代表本功能的目前行為。

## 使用者情境與測試

### 使用者故事 1 - 在遊戲中辨識各類 3D 敵人與目標大樓（優先級：P1）

作為城市守衛，我想在遊戲中看到符合敵人種類與目標用途的 3D 模型，讓普通、人力支援、快速、Boss、地面人物與大樓能被快速辨識。

**優先級理由**：模型是本功能的主要使用者價值；若模型映射或方向錯誤，玩家無法可靠理解戰場。

**獨立測試**：準備所有本機模型輸出後，分別建立每種敵人與大樓；再移除模型輸出重複啟動，確認兩種情況都能進入遊戲。

**驗收情境**：

1. **給定**本機有可用的模型輸出，**當**遊戲建立普通飛機、人力支援飛機、快速飛機、Boss 飛機、一般地面人物、地面 Boss 與目標大樓，**則**每個遊戲物件使用指定的對應模型。
2. **給定**模型沒有內嵌顏色，**當**模型出現在遊戲中，**則**普通／一般地面人物為紅色、人力支援為橙色、快速為藍色、Boss 為紫色、大樓為藍灰色。
3. **給定**多個不同類型的模型同時存在，**當**其中一個模型套用類型色或建立／更新 mesh，**則**其他模型的顏色、模型檔案與方向不被改變；每個模型只使用自己的固定類型色。
4. **給定**飛機沿既有飛行路線移動，**當**模型被建立或更新方向，**則**模型依統一的 Y-up／+Z-forward 契約使機頭朝向飛行方向，不需要為個別模型在遊戲執行時套用方向補正。
5. **給定**人物或大樓模型被建立，**當**它們放置在既有場景位置，**則**人物保持站立；人物移動時臉朝實際移動方向或下一個路徑目標，大樓保持落地，且不改變既有基準玩法包絡；人物中央準心的瞄準取得包絡依 FR-038。
6. **給定**某一個模型缺少、損壞或無法載入，**當**遊戲啟動或生成該類型物件，**則**只有該物件使用既有程序化替代外觀，遊戲不崩潰且其他模型仍可使用。
7. **給定**外部 OBJ 成功載入，**當**模型出現在場景，**則**模型尺寸要足以辨識輪廓，表面
   會呈現日照方向的明暗與適度高光，並在地面或其他模型上產生可見陰影；陰影與高光不得
   以改變玩法碰撞包絡為代價。

### 使用者故事 2 - 使用 RPG 進行有限射程的地面攻擊（優先級：P1）

作為持有 RPG 的玩家，我想看到中央準心並知道 RPG 只能在手槍同等距離內攻擊地面敵人，避免瞄準超出有效距離仍誤射。

**優先級理由**：準心與射程是 RPG 是否可操作、可預期的基本條件。

**獨立測試**：在混合戰鬥與地面戰中裝備 RPG，測試準心顯示、12.0 距離邊界、超距離目標、飛機目標、彈藥與冷卻狀態。

**驗收情境**：

1. **給定**玩家在戰鬥階段裝備 RPG，**當**其他武器準心已隱藏，**則**畫面中央顯示與手槍相同樣式的準心。
2. **給定**玩家切換至手槍或其他武器，**當**武器切換完成，**則**RPG 準心立即隱藏，且不與其他武器準心重疊。
3. **給定**地面敵人與玩家的有效距離小於或等於 12.0，**當**玩家瞄準並射擊，**則**RPG 可建立爆炸中心並遵守既有彈藥與冷卻規則。
4. **給定**地面敵人與玩家的有效距離大於 12.0，**當**玩家射擊，**則**RPG 不消耗彈藥、不進入冷卻且不造成傷害。
5. **給定**中心瞄準到飛機，**當**玩家使用 RPG 射擊，**則**RPG 不把飛機視為合法目標，爆炸也不得傷害飛機。
6. **給定**RPG 已選定合法地面目標，**當**爆炸成立，**則**爆炸半徑內的地面敵人依既有 RPG 傷害規則各結算一次。

### 使用者故事 3 - 以多目標防空炮完成全數鎖定與多導彈齊射（優先級：P1）

作為持有多目標防空炮的玩家，我想在較大的白框中同時追蹤所有符合條件的敵機，等全部小準心完成鎖定後一次發射多枚導彈。

**優先級理由**：多目標鎖定與齊射是多目標防空炮相對於普通防空炮的核心玩法。

**獨立測試**：建立超過六架敵機，其中至少十架同時位於多目標白框內，觀察小準心、個別鎖定進度、全數鎖定閘門與導彈數量。

**驗收情境**：

1. **給定**玩家裝備多目標防空炮並開啟瞄準模式，**當**白框顯示，**則**白框邊長為普通防空炮目前白框的兩倍。
2. **給定**多架敵機可見且位於多目標白框內，**當**玩家持續瞄準，**則**每架敵機都擁有一個小準心與獨立鎖定進度，不受六個目標的固定上限限制。
3. **給定**只有部分小準心完成鎖定，**當**玩家按下射擊，**則**多目標防空炮不發射、不消耗冷卻，並繼續等待未完成的目標。
4. **給定**目前所有有效小準心都完成鎖定，**當**玩家按下射擊，**則**每個目標各建立一枚導引導彈，形成一次齊射；導彈數量與當次有效目標數量相同。
5. **給定**齊射中的某枚導彈已經有目標，**當**該目標被摧毀或導彈失效，**則**該導彈被清除且不得轉移到其他敵機。
6. **給定**敵機在鎖定期間進入或離開白框，**當**目標集合更新，**則**新進入的敵機加入鎖定，離開的敵機依既有衰減規則處理；在所有目前有效目標完成前不得齊射。

### 使用者故事 4 - 透過升級擴大兩種防空炮的白框（優先級：P2）

作為有永久進度的玩家，我想購買白框大小升級，讓普通防空炮與多目標防空炮都能擴大可鎖定範圍。

**優先級理由**：多目標武器的實用性與白框範圍直接相關；共用升級也能讓商店行為保持一致。

**獨立測試**：在商店購買不同等級的白框大小升級，分別進入普通與多目標防空炮瞄準模式，比對升級前後的尺寸與可追蹤目標集合。

**驗收情境**：

1. **給定**玩家尚未購買白框大小升級，**當**使用普通防空炮與多目標防空炮，**則**普通白框使用既有基準，多目標白框使用普通白框的兩倍。
2. **給定**玩家購買一級或多級既有白框大小升級，**當**重新進入任一防空炮瞄準模式，**則**兩種白框都依相同升級倍率放大，且多目標白框仍維持普通白框的兩倍關係。
3. **給定**玩家完成白框大小升級後離開戰鬥並重新載入存檔，**當**再次使用防空炮，**則**升級仍然存在。
4. **給定**玩家使用多目標防空炮，**當**白框變大，**則**可追蹤目標數量只由當前可見敵機與白框範圍決定，不被舊的固定目標數升級限制。

### 使用者故事 5 - 看見受平衡限制的 RPG 與陸地自動防禦射擊（優先級：P1）

作為地面戰玩家，我想看見 RPG 飛出綠色長方體子彈，也想看見陸地自動防禦砲台
發射與敵人相同的短暫曳光彈體；同時自動防禦不能因射程、傷害或射速過高而取代
玩家操作。

**優先級理由**：投射物是射擊回饋的必要可見性；自動防禦若沒有明確的射程、傷害
上限與發射間隔，會使地面戰失去玩家參與與平衡。

**獨立測試**：以無視窗規則測試驗證普通地面敵人的生命值與三發擊殺、Boss 的
50% 傷害上限、短射程與預設 CD；以 scene／controller mock 驗證 RPG 綠色長方體
投射物與自動防禦曳光效果都在開火事件建立，並在生命週期清理。

**驗收情境**：

1. **給定**RPG 射擊命中合法地面目標，**當**玩家按下左鍵，**則**從玩家視角附近
   建立綠色長方體飛行投射物，沿目標方向短暫移動，且保留既有 RPG 爆炸結算。
2. **給定**陸地自動防禦砲台鎖定可攻擊的落地敵人，**當**砲台發射，**則**場景建立
   與敵人攻擊相同樣式的黃色短暫曳光彈體，從砲台位置飛向該目標；視覺效果不取代
   既有規則傷害，也不因效果重複扣血。
3. **給定**一般地面敵人為非 Boss 目標，**當**陸地自動防禦每次命中造成 1 點傷害，
   **則**該敵人最大生命值為 3，需三發才會被擊倒。
4. **給定**地面 Boss，**當**陸地自動防禦持續命中，**則**自動防禦累計最多只能
   造成 Boss 最大生命值 50% 的傷害；達到剩餘 50% 後不再選為自動防禦目標，玩家
   仍可用其他武器完成擊倒。
5. **給定**陸地自動防禦嘗試選擇目標，**當**目標超過短射程上限，**則**不鎖定、
   不發射或啟動射擊冷卻；自動防禦不使用本功能的有限彈藥池。本補充將短射程固定為
   32.0 世界單位並採包含邊界。
6. **給定**陸地自動防禦可以發射，**當**一次發射完成，**則**下一次發射的基準間隔
   等於玩家手槍預設 CD `config.PISTOL_FIRE_COOLDOWN_SECONDS`（目前 0.20 秒）；
   永久冷卻升級可以依既有規則縮短實際間隔，但不能讓未升級基準不同。

### 使用者故事 6 - 在主選單選擇防空瞄準介面（優先級：P1）

作為城市守衛，我想從主選單的設定頁選擇新版或舊版防空武器瞄準介面，讓我可以使用
目前的白框／多目標視覺，或恢復以前以圓圈鎖定飛機的操作提示。

**優先級理由**：瞄準介面是玩家理解鎖定狀態的主要入口；設定入口也必須與開始遊戲、
商店及離開遊戲並列，不能要求玩家修改檔案或重新安裝資產。

**獨立測試**：在已載入 Profile 的主選單按設定，分別選擇兩種防空介面，返回主選單後
進入戰鬥，驗證普通防空炮的視覺切換、模式互斥與多目標介面的完整性。

**驗收情境**：

1. **給定**玩家位於主選單，**當**查看功能按鈕，**則**能看見「設定」按鈕；按下後
   進入防空武器設定頁，且不會啟動戰鬥、商店或離開遊戲。
2. **給定**設定頁已選擇「新版防空瞄準」，**當**玩家在戰鬥中裝備普通防空炮並開啟
   瞄準，**則**顯示現行固定白框與鎖定回饋；裝備多目標防空炮時仍顯示 2 倍白框與
   每目標小準心，不被單一圓圈取代。
3. **給定**設定頁已選擇「舊版圓圈鎖定」，**當**玩家在戰鬥中裝備普通防空炮並開啟
   瞄準，**則**恢復原始 003 的較大固定鎖定框與以目前飛機／鎖定位置為中心的連續
   跟隨圓圈；圓圈由大逐步縮小並在完成時貼近飛機外框，鎖定進度、文字、顏色與目標
   離開時的狀態仍照既有規則反映。新版的動態小準心不在普通防空炮上顯示。
4. **給定**玩家切換手槍、RPG、狙擊槍或多目標防空炮，**當**武器準心更新，**則**舊版
   圓圈只在普通防空炮瞄準模式顯示，其他武器準心與多目標小準心不會重疊或被隱藏。
5. **給定**玩家選定一種介面後返回主選單並再次開始同一程式啟動期間的戰鬥，**則**
   選擇仍然生效；重新啟動遊戲時預設使用新版。介面選擇只改變顯示，不改變射程、傷害、
   鎖定閘門、導彈或升級規則。

### 邊界案例

- 七個來源 STL 中只有部分檔案存在時，各物件必須獨立選用模型或 fallback，不得因單一檔案失敗而阻止遊戲啟動。
- STL 含有退化三角面、無法解析的資料或轉換後 OBJ 無有效面時，該資產必須回報為不可用並使用 fallback；其他資產仍可轉換。
- OBJ 沒有內嵌材質或顏色時，必須使用遊戲類型色，不得顯示成不可辨識的透明或全黑物件。
- RPG 射程等於 12.0 時必須接受；超過 12.0 的最小可測誤差時必須拒絕。
- RPG 沒有中心地面目標、沒有彈藥或仍在冷卻時，不得消耗任何資源或造成傷害。
- 多目標白框內沒有敵機時不建立小準心，也不得發射空齊射。
- 多目標白框內有超過六架敵機時，所有符合條件的敵機都必須可建立小準心與鎖定狀態。
- 多目標鎖定期間一架敵機被摧毀時，必須移除該目標，不得讓齊射閘門卡在已不存在的目標上，也不得把導彈改鎖到其他敵機。
- 多目標鎖定期間關閉瞄準模式、切換武器、進入 game over、返回選單或進入下一波時，所有小準心與鎖定進度必須清除。
- 多目標齊射前若目標已失效，必須先移除失效目標並重新判斷；不得部分發射一個未完成全數鎖定的齊射。
- 多枚導彈同一幀建立時，每枚導彈都必須有唯一識別與固定目標，命中、過期與清除不得互相污染。
- 多目標白框放大不得改變普通防空炮的既有基準尺寸，也不得移除普通防空炮的單目標行為。
- 主選單設定頁若選擇舊版，普通防空炮才可顯示原始 003 的固定框／連續圓圈鎖定；設定
  頁關閉、武器切換或離開戰鬥時不得殘留圓圈、白框或其他瞄準元件。
- 模型同時生成時，任何一個模型的顏色更新不得污染其他模型；模型檔案、角色類型與
  `+Y`／`+Z` 方向契約必須一一對應。
- RPG 的綠色長方體投射物過期、返回選單或進入終止狀態時必須清除；投射物是視覺
  回饋，不得在同一射擊事件重複套用爆炸傷害。
- 陸地自動防禦的可選目標必須落地、存活且位於 32.0 世界單位內；Boss 達到剩餘
  50% 生命後必須離開自動防禦候選集合。
- 原始 STL 與產生的 OBJ 僅作為使用者本機資產；清潔工作區缺少它們時，遊戲仍必須可啟動並完成既有流程。

## 需求

### 功能需求

- **FR-001**：系統必須支援將 `遊戲3d/` 中的七個指定 STL 來源轉換為遊戲可使用的 OBJ 資產，並以穩定名稱對應七種遊戲用途。
- **FR-002**：所有轉換後 OBJ 必須在轉換階段統一為 Y 軸向上；飛機機頭與人物面向必須為 +Z；大樓正面必須使用同一個 +Z 基準。
- **FR-003**：轉換流程必須移除退化面、保留有效面向與法線，且單一資產的轉換失敗不得阻止其他資產使用。
- **FR-004**：遊戲必須依照普通飛機、人力支援飛機、快速飛機、Boss 飛機、一般地面人物、地面 Boss 與目標大樓的映射使用對應 OBJ；人力支援飛機產生的地面人物使用一般地面人物模型。
- **FR-005**：模型資產沒有內嵌顏色時，遊戲必須套用既定類型色：普通／一般地面人物紅色、人力支援橙色、快速藍色、Boss 紫色、大樓藍灰色。
- **FR-006**：模型載入失敗、資產不存在或產出不完整時，遊戲必須使用既有程序化 fallback，並維持原有位置、基準玩法包絡、簡化 box 碰撞與遊戲流程；地面人物的瞄準包絡依 FR-038 處理。
- **FR-007**：資產轉換與產物必須維持本機未追蹤狀態，不得要求將原始 STL 或產生的 OBJ 加入版本庫；轉換流程必須可重複執行以更新本機產物。
- **FR-008**：RPG 在所有可使用 RPG 的戰鬥階段都必須顯示與手槍相同樣式的中央準心。
- **FR-009**：RPG 準心必須與手槍、狙擊槍及防空炮動態準心互斥；武器切換、離開戰鬥或遊戲結束時不得殘留舊準心。
- **FR-010**：RPG 的有效射程必須與手槍相同，使用 12.0 作為包含邊界的最大有效距離；超出射程時不得消耗彈藥、啟動冷卻或造成傷害。
- **FR-011**：RPG 必須只接受地面敵人作為爆炸中心，保留既有爆炸半徑、傷害與每個地面敵人每次爆炸最多一次的規則；飛機不得成為中心或範圍傷害目標。
- **FR-012**：多目標防空炮必須提供獨立武器槽位、瞄準狀態與齊射狀態，且不得取代普通防空炮的單目標鎖定行為。
- **FR-013**：多目標防空炮的白框基準尺寸必須是普通防空炮目前白框的 2.0 倍；普通防空炮白框大小不得因本功能改變。
- **FR-014**：多目標防空炮必須為白框內每一架可見且可鎖定的敵機建立一個小準心與獨立鎖定進度，不得設置 2、6 或其他固定目標數上限。
- **FR-015**：多目標鎖定集合必須依目前可見敵機動態更新；新目標加入、目標離框衰減、目標摧毀移除與瞄準模式關閉重置都必須可被觀察及驗證。
- **FR-016**：多目標防空炮只有在當次所有有效目標都完成鎖定、仍然存在且符合射擊條件時才能射擊；沒有有效目標時不得建立空齊射。
- **FR-017**：一次多目標齊射必須為每個有效目標建立一枚固定目標的導引導彈，導彈數量必須等於當次有效目標數量，並沿用既有命中、過期、爆炸與清除規則。
- **FR-018**：多目標齊射必須以一次武器冷卻控制整個齊射；每枚導彈都必須保留自己的目標識別，不得因其他導彈命中、失效或目標死亡而轉移目標。
- **FR-019**：商店既有的防空炮白框大小升級必須同時套用到普通與多目標防空炮；多目標白框在所有升級等級都必須保持普通白框的 2.0 倍關係。
- **FR-020**：既有的多目標固定數量升級不得再限制多目標防空炮的可鎖定目標數；商店與 HUD 不得將它顯示為仍有效的目標容量規則。
- **FR-021**：所有模型、準心、鎖定集合、齊射導彈與升級行為必須在武器切換、波次切換、game over、返回選單與重新開始時正確清除或重新建立。
- **FR-022**：本功能不得改變既有普通防空炮、狙擊槍、手槍、飛機飛行、城市傷害、波次結算與程序化 fallback 的非目標行為；一般地面敵人生命值與陸地自動防禦規則依 US5 的明確補充更新。
- **FR-023**：合法 RPG 射擊事件必須建立一個從玩家視角附近飛向爆炸中心的綠色長方體視覺投射物；投射物必須有唯一 ID、有限生命週期、固定尺寸與方向，且不得取代既有 RPG 爆炸規則。
- **FR-024**：陸地自動防禦砲台建立時必須有可辨識的砲台外觀；每次實際發射必須建立與敵人地面攻擊相同語意的短暫黃色曳光彈體，從砲台到目標更新位置並於過期或清理時移除。
- **FR-025**：陸地自動防禦的有效射程必須固定為 32.0 世界單位且包含邊界；超出射程、未落地或已死亡的目標不得被選取或觸發發射。自動防禦沒有本功能的有限彈藥池。
- **FR-026**：陸地自動防禦的基準子彈傷害必須為 1；一般生成的非 Boss 地面敵人最大生命值必須為 3，因此需三發命中才擊倒一名普通敵人。
- **FR-027**：陸地自動防禦可以攻擊地面 Boss，但單一自動防禦系統對每個 Boss 的累計傷害不得超過其最大生命值的 50%；Boss 達到該剩餘生命下限後不得再被自動防禦選取。
- **FR-028**：陸地自動防禦的未升級基準發射 CD 必須等於玩家手槍預設 CD `config.PISTOL_FIRE_COOLDOWN_SECONDS`（目前 0.20 秒）；既有永久冷卻升級只依共用升級規則套用。
- **FR-029**：每個飛機、地面人物與目標大樓實例都必須依自己的固定資產用途映射建立，並使用該資產的獨立 mesh／顏色狀態；一個實例的顏色、載入結果或 fallback 不得污染另一個資產。
- **FR-030**：所有實際可用的 OBJ 都必須遵守 Y 軸向上、+Z 為機頭／人物面向的 canonical 契約；飛機只依既有飛行方向更新朝向，地面人物只依水平實際移動方向或下一個路徑目標更新朝向，必須保持 Y 軸向上，不得添加資產類型專屬的 runtime 旋轉補正。
- **FR-031**：Profile 主選單必須提供「設定」按鈕；按下後必須顯示可選的「新版防空瞄準」與「舊版圓圈鎖定」兩個防空介面選項，以及返回主選單操作。
- **FR-032**：新版防空瞄準必須保留現行普通防空白框、鎖定回饋與多目標 2 倍白框／動態小準心；多目標介面不得因選擇舊版而退化成固定數量或單一目標顯示。
- **FR-033**：舊版圓圈鎖定只適用普通防空炮的瞄準模式；開啟時必須恢復原始 003 的較大固定鎖定框，並顯示以目前普通敵機投影位置為中心、從取得範圍依進度縮小至敵機外框的連續圓圈；不得顯示新版普通動態小準心，且必須沿用既有鎖定進度與發射規則。
- **FR-034**：防空介面模式切換、武器切換、關閉瞄準、波次切換、game over、返回主選單與重新開始時，兩種模式的所有互斥 HUD 元件都必須正確顯示或清除，不得同時殘留。
- **FR-035**：介面選擇預設為新版；選擇結果在同一次程式啟動期間返回主選單或重新進入戰鬥時保留，且不得寫入既有 Profile 或改變任何武器／升級規則。
- **FR-036**：外部 OBJ 的可見模型必須以單一均勻比例放大目前基準；飛機／大樓為 `10.0` 倍、陸地型態敵人為 `5.0` 倍。不得按單一軸拉伸，也不得讓放大後的可見 mesh 直接改寫基準 box 碰撞包絡；地面人物的瞄準包絡例外依 FR-038。缺少或 fallback 時維持原本程序化模型大小。
- **FR-037**：成功載入的外部 OBJ 與場景幾何必須使用統一的日照材質；場景須提供暖色方向光、環境填光、物件表面高光與陰影映射，使模型輪廓可由明暗辨識，且不得讓單一模型的材質或顏色狀態污染其他實例。
- **FR-038**：一般／Boss 地面人物的瞄準碰撞盒必須與當前地面敵人的可見外觀包絡相同，供中央準心射線取得手槍、RPG 與狙擊槍目標。成功載入外部 OBJ 時，瞄準盒必須覆蓋該 OBJ 經 runtime 均勻縮放後的實際模型包絡；程序化 fallback 時，瞄準盒必須覆蓋 fallback 的可見模型大小，不得套用外部 OBJ 的 `5.0` 倍倍率。此規則只改變 Entity 的瞄準取得包絡，不得改變人物視覺尺寸、地面位置、RPG 爆炸半徑／傷害、手槍／RPG 射程或陸地自動防禦的 `32.0` 世界單位選取規則。

### 資產方向、矩陣與比例契約

為消除每個模型各自猜測旋轉角度的歧義，本功能固定使用右手座標系：canonical
`+X` 為右方、`+Y` 為上方、`+Z` 為機頭／人物面向。下表的 `(Xc, Yc, Zc)` 是
轉換後座標對來源 `(Xs, Ys, Zs)` 的明確 signed-permutation 映射；所有矩陣行列式
必須為 `+1`，以保留三角面繞序。六個飛機／人物模型已依本機校正工具儲存結果更新；
大樓的校正結果仍未完成，因此暫保留既有 manifest 矩陣，不得視為人工確認完成。轉換器
只套用此表，不在執行時重新推測方向。

| `asset_id` | 來源上方 | 來源前方 | 固定轉換 `(Xc, Yc, Zc)` |
|---|---|---|---|
| `aircraft_normal` | `+Z` | `-Y` | `(Xs, Zs, -Ys)` |
| `aircraft_manpower_support` | `+Z` | `-Y` | `(Xs, Zs, -Ys)` |
| `aircraft_fast` | `+Z` | `-X` | `(-Ys, Zs, -Xs)` |
| `aircraft_boss` | `+Z` | `-Y` | `(Xs, Zs, -Ys)` |
| `crew_normal` | `+Z` | `-Y` | `(Xs, Zs, -Ys)` |
| `crew_boss` | `+Z` | `-Y` | `(Xs, Zs, -Ys)` |
| `target_building` | 未確認 | 未確認 | `(-Xs, Zs, Ys)`（暫保留） |

轉換器在套用矩陣後將模型移至包絡中心；人物與大樓再以可見包絡底面對齊既有地面，
飛機以包絡中心對齊既有飛行位置。為保留模型比例，runtime 使用均勻縮放
`min(target_extent_i / source_extent_i) × visual_scale_multiplier`，其中 `target_extent`
是既有程序化 fallback 包絡：一般飛機 `(1.6, 0.45, 2.8)`、Boss 飛機 `(1.9, 0.60, 3.2)`、
一般人物 `(0.65, 1.8, 0.65)`、Boss 人物 `(0.9, 2.4, 0.9)`、目標大樓 `(10, 12, 9)`。
`visual_scale_multiplier` 只放大可見 OBJ，場景以反向倍率重建簡化 `box` 基準碰撞器，
因此不讓可見尺寸改寫既有玩法包絡；地面人物的中央準心瞄準包絡則例外與其可見外觀
一致。成功載入 OBJ 時，`aim_collider_multiplier` 與陸地模型的 `5.0` 倍可見倍率一致，
使 local `BoxCollider` 經 Entity scale 後覆蓋模型的實際包絡；fallback 不套用外部模型
倍率，使用 unit local box 配合 fallback 的 `target_extent`，因此瞄準盒仍與 fallback
外觀相同。這個瞄準包絡不改變傷害、射程或陸地自動防禦選取規則。
任一來源包絡軸為零或無法套用固定
矩陣時，該資產轉換失敗並回到 fallback。

目前新版飛機／大樓外部模型的可見倍率為 `10.0`，陸地型態敵人為 `5.0`；倍率只作用於
成功載入的 OBJ，不套用到程序化 fallback。陸地模型的 gameplay 基準包絡仍維持既有
target extent，但中央準心使用的瞄準碰撞箱會覆蓋成功載入的陸地模型可見包絡；fallback
則維持與 fallback 外觀相同的碰撞箱大小。

一般飛機包絡適用於 `aircraft_normal`、`aircraft_manpower_support` 與 `aircraft_fast`；
一般人物包絡適用於 `crew_normal` 以及人力支援飛機產生的地面人物。

若人工無法確認來源模型的前方／上方，可執行 `python tools/mark_asset_forward.py` 開啟
來源 STL 校正檢視器。工具會顯示未旋轉模型、標示前／後／左／右／上／下的方向線與前方／上方箭頭，並將每個
模型的 `source_forward`、`source_up` 與可核對的 `source_to_canonical` 寫入本機 ignored
的 `assets/air_defense/models/asset_axis_calibration.json`；確認結果後才更新 manifest。

### 關鍵實體

- **標準化 3D 資產**：一個經來源方向轉換、Y-up／+Z-forward 統一、清理面資料並可選擇性載入的模型產物。
- **資產用途映射**：來源 STL、產出 OBJ、遊戲物件類型、類型色、比例包絡與 fallback 的對應資料。
- **武器準心狀態**：目前武器可見的中央準心或防空白框，以及互斥、顯示、隱藏與重置狀態。
- **多目標鎖定集合**：目前白框內的目標 ID、每個目標的可見性、進度、狀態與是否可射擊資料。
- **導彈齊射**：同一次射擊建立的目標導引導彈集合；每枚導彈具有唯一識別與固定目標。
- **白框大小升級**：永久升級的等級與倍率，會同時影響普通防空炮和多目標防空炮的白框。
- **RPG 視覺投射物**：一次合法 RPG 射擊的短暫綠色長方體，保存起點、目標、進度、尺寸、顏色與過期狀態；不持有傷害權責。
- **陸地自動防禦曳光效果**：一次砲台發射的短暫黃色線性視覺效果，保存砲台／目標位置與射擊序號；不持有碰撞或傷害權責。
- **防空介面模式**：主選單設定所選的新版或舊版顯示模式；只影響普通防空炮的 HUD 呈現，
  不持有鎖定、射擊、傷害或升級規則。
- **模型視覺身份**：由固定 `asset_id`、canonical 軸契約、類型色與獨立 mesh 實例組成的
  非持久化顯示身份；用來防止不同 3D 模型在載入或著色時互相混用。
- **場景日照狀態**：持久於場景 adapter 的方向光、環境光與固定陰影捕捉範圍；只負責
  3D 顯示的明暗、高光與陰影，不參與命中、碰撞、傷害或武器規則。

## 成功標準

### 可量化結果

- **SC-001**：七個指定模型輸出全部存在時，七種遊戲用途 100% 使用正確映射；任一輸出缺少或損壞時，遊戲仍能在一次啟動流程內進入戰鬥並使用對應 fallback。
- **SC-002**：七個模型的方向驗收全部符合 Y-up／+Z-forward；飛機沿路線移動時機頭方向與飛行方向一致，人物保持站立且面向行走方向，大樓保持落地。
- **SC-003**：RPG 準心在所有可用戰鬥階段都能顯示，且射程測試中 12.0 內含邊界可射擊、超過邊界 100% 被拒絕；拒絕操作不消耗彈藥、不啟動冷卻且不造成傷害。
- **SC-004**：多目標防空炮在同時 10 架以上有效敵機位於白框內時，能建立 10 個以上小準心與獨立鎖定狀態，且不因舊的六目標上限截斷。
- **SC-005**：當 N 個多目標全部完成鎖定時，齊射建立且只建立 N 枚固定目標導彈；部分鎖定、空目標、冷卻中或失效目標情況的非預期發射率為 0%。
- **SC-006**：購買白框大小升級後，普通與多目標白框都能在重新進入戰鬥時保留升級；任一升級等級下，多目標白框與普通白框的尺寸比例維持 2.0。
- **SC-007**：完整回歸測試中，既有飛機、地面敵人、普通防空炮、狙擊槍、手槍、波次、game over、重置與 fallback 行為均維持原有通過結果。
- **SC-008**：在既有 1280×720、A=5 的整合場景中暖機 5 秒後觀察 30 秒，平均畫面更新率至少 60；若環境沒有圖形介面，必須記錄為未量測而不得宣稱通過。
- **SC-009**：每次合法 RPG 射擊都可觀察到唯一的綠色長方體投射物；投射物在有限時間內沿目標方向更新並清理，不造成重複傷害。
- **SC-010**：陸地自動防禦在 32.0 世界單位內可見砲台與黃色曳光發射效果；超過 32.0 的目標不會被選取，普通敵人三發擊倒，Boss 自動防禦累計傷害最多為 50%。
- **SC-011**：陸地自動防禦未升級發射間隔與手槍預設 CD 完全相等；既有 cooldown 升級後仍可由同一規則來源推導實際間隔。
- **SC-012**：同時建立四種飛機、兩種地面人物與大樓時，100% 的實例都使用正確資產映射、+Y／+Z 方向身份與各自類型色；任一實例變色或 fallback 不會改變其他實例。
- **SC-013**：玩家在主選單按一次「設定」即可進入防空介面頁，且頁面提供新版、舊版與返回主選單三項可操作結果；不會觸發戰鬥或破壞 Profile。
- **SC-014**：新版普通防空瞄準顯示固定白框與新版動態準心；舊版普通防空瞄準顯示原始 003 的固定框與連續縮小圓圈，兩者的動態鎖定標記在同一次更新中互斥；多目標防空在兩種設定下都維持 10+ 目標動態小準心與既有齊射規則。
- **SC-015**：在同一次程式啟動期間切換設定、返回主選單並重新進入戰鬥後，所選介面 100% 保持；重新啟動的預設模式為新版，且所有武器射程、傷害、鎖定與升級測試結果與未切換模式相同。
- **SC-016**：七個外部 OBJ 的可見 runtime 尺寸都維持三軸同倍率；飛機／大樓為 `10.0` 倍、陸地型態敵人為 `5.0` 倍。飛機／大樓的基準 Entity box 世界包絡維持既有 target extent，地面人物的中央準心瞄準 box 必須與成功載入的陸地模型可見包絡相同；fallback 的瞄準 box 必須與 fallback 可見大小相同，且 fallback 不套用外部模型倍率。
- **SC-017**：圖形 smoke 中成功載入的外部 OBJ 與地面可觀察到方向光造成的明暗層次、至少一處表面高光與投射陰影；模型顏色仍按 asset ID／角色隔離，且 shader／光源建立失敗時遊戲仍可用既有 fallback 啟動。

## 假設

- `遊戲3d/` 中的 STL 是使用者提供的本機原始資產；本功能不處理重新授權、公開發佈或將資產提交到版本庫。
- OBJ 轉換階段會為每個來源模型保留固定方向設定；遊戲執行時不新增每個模型的旋轉補正。所有輸出必須遵守 Y 軸向上與 +Z 機頭／人物面向。
- 來源模型沒有可靠的內嵌材質色，因此模型顏色由遊戲物件類型色提供；本功能不新增貼圖、音效或材質分區，但使用統一的日照／陰影 shader 提供明暗與受控高光。
- 模型顏色採每個資產實例的固定類型色與獨立 mesh 狀態，避免共享材質造成顏色混用；不額外加入貼圖或材質分區。
- 模型會依目前程序化物件的玩法包絡調整比例；碰撞仍使用簡化 box，不改用高面數網格碰撞。
- RPG 保留既有預設爆炸半徑 6、傷害 35、冷卻 2.5 秒與每小關 3 發；本功能新增準心、綠色長方體視覺投射物並把有效射程改為手槍的 12.0，爆炸傷害仍只在合法射擊事件結算一次。
- 本補充將「普通」定義為一般生成的非 Boss 地面敵人：其最大生命值為 3，自動防禦每發造成 1 點傷害，因此三發擊倒；地面 Boss 維持 `GROUND_BOSS_HEALTH=10`，自動防禦最多將其打至剩餘 5 點生命（最大生命值的 50%），之後由玩家武器處理。
- 陸地自動防禦的基準射程為 32.0 世界單位、基準傷害為 1、基準發射 CD 與手槍預設 CD 同為 0.20 秒；永久冷卻升級可沿用既有共用倍率。
- 多目標防空炮的目標集合沒有固定數量上限，實際數量只受當前波次中可見、位於白框內且仍有效的敵機數量限制；目標進入集合時開始獨立鎖定，離開集合時依既有衰減規則移除。
- 多目標防空炮的白框大小共用既有白框升級；多目標基準尺寸固定為普通防空炮基準的兩倍。舊的固定目標容量資料只作相容處理，不再影響遊戲行為。
- 多目標齊射使用既有導引導彈的目標識別、命中傷害、過期與清理語意；齊射觸發時不直接對飛機造成額外一次傷害。
- 防空介面選擇是本次程式啟動期間的顯示偏好，不納入既有 Profile schema；新版為每次新啟動的預設，舊版只在玩家主動選擇後生效。
- 若模型方向仍無法由檔案名稱或幾何可靠判定，使用者可執行本功能提供的 `tools/mark_asset_forward.py`，以未旋轉 STL 的彩色軸向檢視器標記每個模型的來源前方與上方；工具輸出只作為 manifest 校正輸入，不在 runtime 臨時猜測或疊加旋轉。
- 來源軸的人工判定語意固定為：有螺旋槳的飛機以螺旋槳／機鼻側為前方；人物以腳到頭為上方、以有臉的一側為前方。這些判定只在校正工具中使用，確認前不得直接臆測新的 manifest 矩陣。
- 本功能沿用既有 `air_defense` 的 Ursina 3D 執行環境，這是針對本專案已有 3D 場景、
  相機、模型載入與即時碰撞需求的明確技術例外；若改以憲章預設的 Pygame 重寫，將
  需要另行改造整個 `air_defense` 的 3D 顯示與輸入層，超出本功能範圍。影響限制在
  `air_defense/scene.py`、`air_defense/hud.py` 與 `air_defense/main.py` 的既有 Ursina
  adapter，純規則、升級、存檔與轉換器仍不匯入 Ursina。已知風險是 Ursina 版本／平台
  差異可能影響 OBJ 載入或圖形 smoke；以釘選 `ursina==8.3.0`、程序化 fallback、純規則
  測試與手動驗收降低風險。此功能不執行遷移；若未來要回到 Pygame，必須另建遷移規格，
  先完成 API、模型載入、碰撞與手動驗收後才切換，不得在本功能中隱含遷移。
- 成功標準與手動效能流程中的 `A=5` 指既有 Profile 的 `maximum_aircraft_count` 設定為
  5；它不是多目標鎖定容量，也不覆寫「10+ 合成／受控候選」的規則測試要求。
- 本功能的規格、後續計畫、任務、檢核清單與驗證文件均使用繁體中文，並遵守專案憲章的 SDD 與品質門檻。
