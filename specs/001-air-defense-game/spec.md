# Feature Specification: 3D 防空守衛無限模式

**Feature Branch**: `001-air-defense-game`

**Created**: 2026-08-26

**Status**: Draft

**Input**: User description: "製作一個第一人稱 3D 防空遊戲：玩家在小型城市街區使用物品欄中的防空炮，瞄準自殺式攻擊大樓的戰鬥機；鎖定後擊落飛機，再從物品欄切換狙擊槍，擊倒該飛機帶來的持槍乘員，持續循環直到玩家死亡。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 攔截攻擊大樓的戰鬥機 (Priority: P1)

作為守衛城市大樓的玩家，我想從物品欄選用防空炮、辨識飛機是否已被鎖定，並在飛機撞樓前將它擊落，才能保護大樓並開始下一階段戰鬥。

**Why this priority**: 攔截自殺式空襲是整個遊戲最核心的目標；沒有這個流程，後續地面戰鬥就沒有觸發來源。

**Independent Test**: 從主選單開始一局，按 `1` 選用防空炮並完成一次成功鎖定與發射，或刻意不發射讓飛機撞擊大樓，以確認成功與失敗兩條空襲流程都可獨立驗證。

**Acceptance Scenarios**:

1. **Given** 玩家在空襲階段且物品欄提供防空炮，**When** 玩家按下 `1`，**Then** 玩家進入防空炮瞄準模式，畫面中央顯示白色正方形瞄準框。
2. **Given** 戰鬥機正沿直線俯衝攻擊指定大樓，**When** 玩家將瞄準框持續對準飛機，**Then** 瞄準框以每 0.12 秒切換一次可見/不可見的紅色閃爍，直到連續瞄準滿 3 秒後變成穩定綠色。
3. **Given** 瞄準框為穩定綠色，**When** 玩家按下射擊鍵，**Then** 一枚導引彈擊落戰鬥機，並在飛機撞擊大樓前結束空襲。
4. **Given** 瞄準框尚未變綠，**When** 玩家按下射擊鍵，**Then** 防空炮不發射，玩家必須繼續完成鎖定。
5. **Given** 飛機在尚未被擊落前碰撞大樓，**When** 碰撞發生，**Then** 該局立即進入空襲失敗狀態。

---

### User Story 2 - 在墜機後切換狙擊槍並擊倒乘員 (Priority: P2)

作為空襲後仍存活的玩家，我想在飛機墜落後面對該機乘員的持槍反擊，直接從物品欄切換狙擊槍，以保護自己並清除這次墜機帶來的敵人。

**Why this priority**: 地面戰讓玩家必須在空戰武器與人員戰鬥之間作出即時切換，是本遊戲區別於單純打飛機遊戲的主要玩法。

**Independent Test**: 將遊戲置於一架飛機已墜落的測試狀態，確認一次只生成該架飛機的 2–5 名乘員，使用物品欄切換武器、受到攻擊並擊倒全部乘員。

**Acceptance Scenarios**:

1. **Given** 戰鬥機已被擊落，**When** 墜機事件完成，**Then** 只出現該架飛機帶來的一組 2–5 名持槍乘員；每名乘員被分配預設掩體節點與掩護射手或推進射手角色，且不會額外生成地面增援。
2. **Given** 乘員從墜機點跑出並使用掩體與分組戰術，**When** 玩家在物品欄按下 `2`，**Then** 玩家直接切換至狙擊槍並能進行狙擊瞄準，不受與武器架距離限制。
3. **Given** 玩家持有狙擊槍，**When** 有效命中一名乘員，**Then** 該乘員立即被擊倒；狙擊槍具備無限彈藥，但射擊受到冷卻限制。
4. **Given** 乘員仍存活，**When** 乘員的射擊命中玩家，**Then** 玩家可見生命值下降；生命值歸零時該局立即失敗。
5. **Given** 當架飛機的所有乘員都被擊倒，**When** 最後一名乘員倒下，**Then** 地面戰階段結束並準備下一次空襲。

---

### User Story 3 - 持續防守並查看本局統計 (Priority: P3)

作為想挑戰更高紀錄的玩家，我想在清除一架飛機的乘員後立即迎接下一架飛機，並在死亡後查看本局統計與返回主選單。

**Why this priority**: 無限循環與統計讓核心流程具備重玩價值，也讓玩家能比較存活時間、擊落飛機數與擊倒敵人數。

**Independent Test**: 完成至少一個「擊落飛機—清除乘員—下一架空襲」循環，再以飛機撞樓或生命值歸零結束遊戲，確認失敗畫面與統計資訊正確顯示。

**Acceptance Scenarios**:

1. **Given** 當架飛機的乘員全部被擊倒，**When** 地面戰清場完成，**Then** 下一架戰鬥機立即開始沿攻擊路線接近大樓，遊戲不進入勝利畫面。
2. **Given** 玩家在空襲或地面戰中生命值歸零，**When** 死亡狀態成立，**Then** 遊戲停止接受戰鬥輸入並顯示失敗原因、存活時間、擊落飛機數與擊倒敵人數。
3. **Given** 玩家在失敗畫面，**When** 玩家點擊「返回主選單」按鈕或按下返回快捷鍵，**Then** 本局狀態被清除，下一局從滿生命值與起始防守點重新開始。

### Edge Cases

- 玩家在鎖定期間將瞄準框移離飛機，或飛機被場景物件遮擋時，鎖定進度立即清除，瞄準框回到白色。
- 玩家按下物品欄中不符合當前階段的武器鍵時，遊戲不得切換到不適用武器；玩家最多同時裝備一把武器。
- 玩家清除乘員後仍持有狙擊槍時，下一架飛機仍會立即開始接近；玩家不能用狙擊槍鎖定或擊落飛機，HUD 必須提示使用物品欄按 `1` 切換防空炮，若未及時換回而使飛機碰撞大樓則固定判定為空襲失敗，且不得自動換槍。
- 導引彈擊落飛機與飛機碰撞大樓幾乎同時發生時，以先成立的事件作為結果：先擊落則進入墜機事件，先碰撞則立即失敗。
- 每架飛機的乘員數量必須落在 2–5 名之間，且同一架飛機清場後不得再次生成地面乘員。
- 玩家在任一階段死亡後，剩餘敵人、飛機與武器互動都停止，避免重複計分或重複觸發失敗。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 遊戲 MUST 提供主選單的「開始遊戲」與「離開遊戲」可點擊按鈕，並提供鍵盤快捷操作，讓玩家開始新局或離開遊戲。
- **FR-002**: 新局 MUST 將玩家放置在包含目標大樓、防守點、物品欄、武器展示架、街道與掩體的小型城市街區，並重置本局生命值與統計。
- **FR-003**: 遊戲 MUST 支援 PC 鍵鼠操作：WASD 移動、滑鼠轉向、`1` 從物品欄直接裝備防空炮、`2` 從物品欄直接裝備狙擊槍、左鍵射擊、右鍵狙擊瞄準；並可保留 E 拾取/互動與 G 丟下手上武器作為額外操作。
- **FR-004**: 玩家從物品欄選用防空炮後，遊戲 MUST 進入防空瞄準模式，並在畫面中央顯示白色正方形瞄準框。
- **FR-005**: 遊戲 MUST 讓單架戰鬥機沿直線自殺式俯衝路線攻擊指定大樓；當預估撞樓時間小於或等於 8 秒時，HUD MUST 顯示包含「空襲警告」文字或圖示的危險提示。
- **FR-006**: 當瞄準框持續對準且未被遮擋的戰鬥機時，瞄準框 MUST 以每 0.12 秒切換一次可見/不可見的紅色閃爍；連續 3 秒後 MUST 變成穩定、不閃爍的綠色。失去目標或視線被遮擋時 MUST 立即重置為白色。
- **FR-007**: 防空炮 MUST 只有在瞄準框為穩定綠色時才能發射；發射後 MUST 使用一枚導引彈擊落當前戰鬥機，並具備射擊冷卻與無限彈藥規則。
- **FR-008**: 若戰鬥機在被擊落前碰撞目標大樓，遊戲 MUST 立即判定玩家失敗並停止該局戰鬥。
- **FR-009**: 每架被擊落的戰鬥機 MUST 只生成一次 2–5 名乘員；每名乘員 MUST 在生成時取得預設掩體節點與掩護射手或推進射手角色，掩護射手留在掩體攻擊，推進射手依序在預設掩體間移動後攻擊玩家，所有射擊 MUST 遵守個別冷卻，且不得出現額外地面增援。
- **FR-010**: 玩家 MUST 能從物品欄按 `2` 直接切換狙擊槍，無須前往武器架；狙擊槍有效命中 MUST 立即擊倒一名乘員，並具備無限彈藥與射擊冷卻。
- **FR-011**: 遊戲 MUST 在 HUD 顯示玩家生命值；敵人命中玩家時生命值 MUST 下降，生命值歸零 MUST 判定玩家失敗。
- **FR-012**: 當前飛機的所有乘員被擊倒後，遊戲 MUST 立即開始下一次戰鬥機空襲；遊戲 MUST 持續循環直到玩家死亡，不提供固定終點或勝利畫面。
- **FR-013**: HUD MUST 顯示生命值、空襲警告、鎖定瞄準框、存活時間、擊落飛機數與擊倒敵人數。
- **FR-014**: 失敗畫面 MUST 顯示失敗原因與本局統計，並提供返回主選單的操作；返回主選單後 MUST 清除本局中的敵人、飛機、武器狀態與統計。

### Key Entities *(include if feature involves data)*

- **玩家**：代表受控制的防守者，包含位置、生命值、視角、目前持有武器與本局狀態。
- **防空炮**：可由物品欄第 1 格直接選用的空襲武器，也可透過額外互動從地面拾取或丟下；包含鎖定狀態、發射冷卻與目前目標。
- **狙擊槍**：可由物品欄第 2 格直接選用的地面戰武器，也可透過額外互動從武器架拾取或丟下；包含瞄準狀態、射擊冷卻與命中結果。
- **戰鬥機**：以大樓為目標進行直線俯衝的空中威脅，包含接近、被擊落與撞樓結果。
- **目標大樓**：玩家需要保護的建築物，包含可觸發失敗的碰撞範圍。
- **乘員小隊**：由單架墜落戰鬥機帶來的 2–5 名持槍敵人，包含存活狀態、掩體位置與分組行為。
- **本局統計**：記錄存活時間、擊落飛機數、擊倒敵人數與最近一次失敗原因。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新玩家在開始新局後 30 秒內，能看懂物品欄、按 `1` 裝備防空炮並看到中央瞄準框。
- **SC-002**: 在 10 次鎖定測試中，瞄準框每次都會先以每 0.12 秒切換一次可見/不可見的紅色閃爍，持續對準 3 秒後穩定呈現綠色；中斷瞄準時每次都回到白色。
- **SC-003**: 在 5 次完整流程測試中，玩家都能完成「擊落一架戰鬥機、看見 2–5 名乘員、手動切換狙擊槍、清除該組乘員、觸發下一架空襲」而不需要重開遊戲。
- **SC-004**: 飛機碰撞大樓或玩家生命值歸零後，遊戲都能在 1 秒內停止戰鬥並顯示正確失敗原因與本局統計。
- **SC-005**: 在 5 次墜機測試中，每架飛機都只生成一次 2–5 名乘員，清場後不再生成該架飛機的地面敵人。
- **SC-006**: 至少 4/5 名首次遊玩的測試者能僅依靠 HUD 分辨「尚未鎖定、正在鎖定、可以發射、需要切換狙擊槍」四種核心狀態。

## Acceptance Parameters

- 空襲警告的觸發門檻為戰鬥機預估撞樓時間小於或等於 8 秒；警告至少包含文字「空襲警告」或等義圖示。
- 鎖定中的紅框每 0.12 秒切換一次可見/不可見，完整閃爍週期為 0.24 秒；鎖定滿 3.00 秒後轉為穩定綠框。
- 乘員生成時固定分配掩體節點與角色；掩護射手留在目前掩體，推進射手每 2.0 秒才可嘗試前往下一個預設節點，不建立臨時增援路徑。
- 失敗事件成立後，從事件時間戳到停止戰鬥更新並顯示失敗畫面的時間 MUST 不超過 1 秒。
- 在一架飛機、一道目標大樓與最多五名乘員的場景負載下，遊戲目標為維持 60 FPS；Quickstart 需記錄量測結果與硬體限制。

## Assumptions

- 遊戲是單人、桌面平台、PC 鍵鼠操作；不包含多人連線、存檔、帳號或網路功能。
- 最新需求覆蓋先前的固定 3 分鐘生存規則：本版本沒有時間勝利條件，而是無限循環直到玩家死亡。
- 最新需求也覆蓋先前的持續地面增援規則：每架飛機只帶來一次 2–5 名乘員，沒有地面增援。
- 同一時間只處理一架戰鬥機；該機被擊落後才進入其乘員的地面戰，清場後立即迎接下一架。
- 戰鬥機本身只以撞擊大樓作為空襲威脅，不另外向玩家射擊。
- 地面戰採卡通街機風格；環境與角色可使用合法免費資產搭配簡單幾何資產，外部資產不可成為遊戲啟動的必要單點依賴。
- 玩家每局從完整生命值開始；生命值與敵人傷害的平衡數值集中管理，但不改變「生命值歸零即失敗」的規則。
- 本功能必須提供真實 3D 第一人稱場景，因此不沿用既有 Pygame 的 2D 視窗層；影響僅限本功能新增的遊戲模組與其專用依賴，既有教學程式維持不變，若撤回本功能可移除該獨立模組與依賴，不需遷移既有程式。
- 既有教學程式維持不變；本規格只定義遊戲體驗與可驗證的玩家行為，具體製作方式留待後續規劃文件。

## Constitution Exception Record

- **Principle IV feature-scoped exception**: 憲章中的「球未發射、球遺失與勝利」是既有打磚塊遊戲的狀態範例；本功能是無限循環的防空遊戲，依需求不提供勝利畫面，也不建立球物件。對應的可驗證狀態改為 `MAIN_MENU`、`AIRSTRIKE`、`GROUND_COMBAT` 與 `GAME_OVER`，並保留明確的進入、重置與終止條件。
- **Principle V feature-scoped exception**: 真實 3D 第一人稱需求使用 Ursina 8.3.0/Panda3D，而不是既有 Pygame 2D 視窗層；影響限制在本功能的獨立模組與 Python 3.12+ 專用依賴。風險是新增執行環境與圖形依賴，透過版本釘選、離線可啟動的程序化幾何 fallback、既有程式隔離與專用 Quickstart 控制；撤回時移除本功能模組與依賴，不需遷移既有教學程式。
- **理由與風險**: 強行加入球狀態或勝利狀態會違反 FR-012 並增加無關複雜度；風險是狀態範本與既有打磚塊文件不同，透過明確狀態轉移、事件去重與完整 Quickstart 驗證控制風險。
- **範圍與回復**: 例外只適用於 `specs/001-air-defense-game/` 的本功能，不改變憲章、不修改既有 `day1/` 或 `day2/`；撤回本功能時移除獨立遊戲模組、依賴與本功能文件即可。
- **確認**: 專案負責人在需求討論及本次修正中已選定真實 3D、無限循環設計，並確認上述範圍化例外、風險及回復邊界。
