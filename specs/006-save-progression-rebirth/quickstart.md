# 快速驗證指南：持久化存檔、進度與重生戰役

**功能**：`006-save-progression-rebirth`

**參考**：[spec.md](./spec.md)、[data-model.md](./data-model.md)、[UI 契約](./contracts/ui.md)

## 前置條件

- Windows 桌面環境與可顯示 3D 視窗的顯示器。
- Python 3.12 或更新版本。
- 從專案根目錄執行命令。
- 已安裝 `requirements-game.txt` 中的既有 `ursina==8.3.0`。

若目前環境尚未安裝遊戲依賴：

```powershell
python -m pip install -r requirements-game.txt
```

## 手動驗收流程

### 五存檔與主選單

1. 啟動遊戲，分別建立 1 號與 2 號存檔的不同金幣或升級。
2. 關閉並重新啟動，選擇 1 號，再選擇 2 號。
3. 確認兩個欄位資料互不影響。
4. 確認選擇存檔後只出現開始遊戲、升級商店與重生三個主要功能，不會自動進入戰鬥。
5. 使用滑鼠點擊 1～5 號欄位，確認每次都載入被點擊的欄位並進入其主選單；不依賴數字鍵也能完成選檔。
6. 對一個非空欄位點擊「刪除」，確認第一次點擊只顯示確認／取消，不會立即刪除。
7. 點擊「取消」，確認該欄位仍存在；再次點擊「刪除」後選擇「確認刪除」，確認只移除目標欄位，其他四個欄位仍可載入。
8. 確認空白欄位的刪除按鈕不可用，且重複點擊確認或在選檔畫面以外均不會刪除資料。

### A=2 的小關進度

1. 從 1 號存檔開始遊戲，確認第一個小關為 `1-1`。
2. 完成 `1-1`，確認只獲得一次金幣並返回主選單。
3. 確認主選單保存最近完成的 `1-1` 紀錄，但該紀錄不是續關點。
4. 在同次程式執行期間再次開始，確認暫存指標前進至 `1-2`，而不是重新從 `1-1` 開始。
5. 重新載入同一存檔，確認仍從 `1-1` 開始，但最近完成紀錄仍顯示 `1-1`。
6. 依序完成 `2-1`、`2-2`、`2-3`、`2-4`、`2-5`，確認只有 `a==A` 的後段小關出現魔王。
7. 完成 `2-5` 後確認主選單顯示重生資格、下一次手動開始預設為 `1-1`，且沒有自動開始下一局。

### 死亡、重載與重生

1. 在任一小關中死亡，確認不發放該次完成獎勵、清除敵人／城市／彈藥／砲塔，並返回主選單。
2. 重新開始遊戲，確認從 `1-1` 且 HP 等於永久最大 HP 開始。
3. 確認死亡後關閉程式再載入同一存檔，重生資格仍存在。
4. 使用剛好足夠的金幣重生，確認費用為 `1000 * (目前重生次數+1)`、金幣歸零、A 增加、升級上限提高，且不自動開始遊戲。
5. 下一次開始確認新 A 仍從 `1-1`，並測試目前 A 的最終小關才有魔王階段。

### 升級、回血與暫存狀態

1. 在商店購買最大 HP、鎧甲、鎖定時間、白框大小、冷卻與一項武器解鎖。
2. 完成一局、死亡、重生並重新載入，確認永久資料仍存在。
3. 受到傷害後等待少於 5 秒，確認不回血；連續 5 秒未受傷後確認以每秒 2 HP 緩慢回血。
4. 確認每個小關自動回血總量最多為有效最大 HP 的 20%，再次受傷會重新計時但不增加小關總額度。
5. 重複受傷直到回血額度用完，確認本小關不再自動回血；開始新小關後額度重新建立。
6. 進入升級商店，確認每個升級按鈕以「編號名稱(目前等級/上限)價格元」單行顯示，例如格式 `1鎧甲(1/4)220元`；編號依商店目錄順序，目前目錄的鎧甲項目應顯示為 `2鎧甲(1/4)220元`，且沒有重複的白色升級明細文字；購買後等級、上限與價格文字立即刷新。
7. 開始新小關，確認 HP、城市血量、敵人、彈藥與砲塔都是新的狀態。

### 武器與 E/G

1. 在空戰、混合戰鬥與地面戰鬥中使用 1～5 切換所有已解鎖武器。
2. 確認單目標防空炮只能攻擊飛機，狙擊槍與手槍只能攻擊地面敵人。
3. 使用 RPG 攻擊一群地面敵人，確認範圍內每個地面敵人只受一次傷害、RPG 不可選取或傷害飛機，並正確消耗冷卻與彈藥；以 RPG 擊倒最後一批敵人後，確認小關完成、金幣只結算一次並返回主選單。
4. 使用多目標防空炮鎖定多台飛機，確認 HUD 顯示全部鎖定並依購買上限射擊。
5. 確認陸地自動防禦只攻擊已落地的非魔王小兵，不攻擊下降中的敵人，且最多六台；每台每小關 20 發、每次射擊冷卻 1.5 秒、每次命中傷害 20。
6. 在所有畫面按 E 與 G，確認沒有互動、拾取、丟棄、切換或攻擊效果，且 HUD 沒有相關提示。
7. 在商店購買陸地自動防禦解鎖與容量升級，確認每個新小關自動建立前 N 個固定位置的砲塔，
   不提供戰鬥中購買或任意放置，且相同購買操作 ID 重送回呼不會再次扣款。

### 損壞存檔

1. 將任一存檔內容改成不完整或格式錯誤的資料。
2. 載入該欄位，確認遊戲不崩潰、顯示繁體中文警告並保留原始損壞資料。
3. 載入其他四個欄位，確認其資料未被改變。

## 邏輯邊界驗證

至少執行下列純邏輯案例：

| 案例 | 預期結果 |
|---|---|
| A=2、3、4、5 | 所有有效 a-b 與排列符合公式 |
| A=19 | 生成成功，不受 18 或 4 限制 |
| `a<A` | 所有 b 都沒有魔王 |
| `a==A` | 只有 b 超過 `A+1` 後出現魔王 |
| 重複完成回呼 | 金幣與暫存進度各只改變一次 |
| 重複重生回呼 | 金幣與重生次數只改變一次 |
| 無目標／超距離／冷卻中／無彈藥 | 不造成傷害且不繞過限制 |
| RPG 多次碰撞通知與最後一批清除 | 每個地面敵人每次爆炸只受一次傷害，飛機不受傷害；清除整個小關後只結算一次 |
| 下降中的小兵 | 可被合法命中，但不移動、不攻擊、不造成城市傷害 |

## 效能驗證

使用既有 FPS 顯示與測試記錄兩個場景：

1. A=5 的空戰場景，包含 5 台飛機、多目標鎖定與導引飛彈。
2. 地面場景，包含最多 6 台固定砲塔與目前關卡可產生的地面敵人。

每個場景暖機 5 秒、觀察 30 秒並每秒記錄一次 FPS。通過條件為平均 FPS 至少 60，且不得有
超過 5 秒的連續低於 45 FPS 區段；記錄作業系統、Python 版本、解析度與硬體摘要。A 大於
18 的案例只要求純邏輯生成不被拒絕，不得藉由偷偷限制 A 來達成效能目標。

若測試環境沒有可用的圖形顯示器，須標記圖形與 FPS 結果為未測量，保留自動化證據，不得宣稱
未測量的手動結果已通過。
